OVERVIEW

Executive Summary: Evolution of SeChat

⚠️ Current Limitations

  • Monolithic FastAPI process with in-memory connection manager.
  • SQLite file locks under concurrent write operations.
  • Cannot scale beyond a single server instance.
  • Loss of connections during network hiccups.

🚀 Proposed System

  • Decoupled Pub/Sub Broker for cross-process broadcasting.
  • Central Connection Registry/Pool for multi-worker clusters.
  • Integrated Crypto Layer (AES-GCM + KDF) for security.
  • Monitoring & Rate Limiting guardrails for production stability.

📈 Key Impact

  • Infinite Horizontal Scalability (Add WS nodes dynamically).
  • High Availability & Reconnect Resilience.
  • Enterprise-grade Security (E2EE/MLS roadmap).
  • Protection against DDoS and message flooding.

Critical Architectural Bottlenecks

  • Tightly Coupled Monolith: HTTP REST, authentication, and WebSocket handling run within a single process.
  • In-Memory State Lock: Active connections live exclusively in Python process RAM. Running 2 worker processes causes lost messages.
  • Database Concurrency Barrier: Synchronous SQLite writes create lock contention during concurrent chat surges.
PROPOSED MODEL

Proposed System & Architecture

Decoupled Component Blueprint

  • Clients: Browser/Mobile connecting via REST & WS Gateways.
  • REST API (Auth + Room): Dedicated stateless service for auth & metadata.
  • WebSocket Gateway: High-concurrency edge nodes handling TCP framing.
  • Connection Pool / Registry: Central session & worker route tracker.
  • Pub/Sub Broker: Redis-based event bus for multi-node messaging.
  • Crypto Layer: AES-GCM + KDF payload encryption module.

Core Architecture Enhancements

  • Pub/Sub Dissemination: Decouples message broadcasting from individual WS server memory.
  • Connection Registry & Pool: Supports multi-worker clusters & handles transparent client reconnects.
  • Application-Layer Multicast: Logical group delivery model ensuring zero unnecessary message fanout.
  • Crypto Evolution: Key management framework ready to step up to MLS / Double Ratchet protocols.

BENEFITS

Key Technological Pillar Advantages

1. Low Latency Fanout

Pub/Sub backbone achieves sub-20ms message routing across thousands of simultaneous channel subscribers.

2. Zero Downtime Scaling

Add or remove WebSocket Gateway instances dynamically to match real-time traffic spikes effortlessly.

3. Cryptographic Security

AES-GCM payload encryption ensures total message privacy across untrusted network hops.

4. Operational Health

Integrated rate limits prevent spam attacks while real-time metrics provide system-wide visibility.
